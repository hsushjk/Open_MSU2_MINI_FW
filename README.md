# Open_MSU2_MINI_FW
| `0A 09` | `0A 09 秒数 00 00 00` | 设置开机画面停留秒数（1..60），回 `0A 09 06 秒数 00 00` |


MSU2_MINI（Moriateliers 小副屏，CH32X033F8P6 + ST7735S 160×80 + P25D80H 1 MB SPI NOR）的**从零重写固件**。

不依赖原厂固件、不调用任何 WCH 库：启动、USB CDC、SPI 屏驱动、ADC 触摸、看门狗、SPI flash 全部自己写，`-nostdlib` 构建。

- 当前版本：**v33**
- 产物：`build/msu2_proto_fw.hex`（约 28.3 KB）
- 授权：MIT

## 为什么重写

原厂固件有几处会直接导致“花屏 / 卡死 / 画面永久错位”的设计，重写时逐一避开了：

| 原厂行为 | 后果 | 本固件的做法 |
|---|---|---|
| 接收环满了直接丢整包 64 字节 | 少像素 → 后续像素整体前移 → 永久错位 | 环满只 NAK，让主机等，**绝不丢字节** |
| 收流中途断掉后不归零 | 后面的命令字节被当像素吃掉，画面冻结且切页也救不回来 | 30 ms 无新字节 / 400 ms 绝对期限 → 作废本段并归零 |
| 没有看门狗 | 一旦死循环只能拔电 | IWDG（约 1.6 s），异常向量全部落进死循环 → 自动复位重启 |
| 无逐帧回执 | 主机不知道这帧有没有收全 | 每帧一个裁决字节（`0x06` 收齐 / `0x15` 少收） |

## 硬件

| 功能 | 引脚 |
|---|---|
| SPI SCLK / MOSI | PA5 / PA7 |
| LCD D/C（与 flash MISO 共用） | PA6 |
| LCD CS / RST | PC3 / PA0 |
| flash CS | PB7 |
| 触摸电极（ADC 通道 9，TKey 模式） | PB1 |
| USB D- / D+ | PC16 / PC17 |
| 调试串口 TX2 / RX2 | PA2 / PA3（115200） |

> **JP1 / JP2 / JP3 暂不支持。** 它们是未焊接的裸焊盘，而且和外设抢资源：JP2/JP3 的 SPI 片选（PA1/PA4）与屏共用 SPI 总线，`PA6` 还兼着 flash MISO 与屏 D/C；JP1 的 I2C（PC18/PC19）与 SWD 调试口复用。要用请先自行评估分时与冲突。

## 构建

需要 `riscv-none-elf-gcc`（xpack 14.x 即可）：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Variant proto
```

产物在 `build/msu2_proto_fw.hex`。

- 脚本必须保持**纯 ASCII**（PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI）。
- `build.ps1` 时不时返回退出码 1，那是 GCC 往 stderr 打东西被 PowerShell 当成错误；**只有出现 `error:` 才是真错**。

## 抹掉板载 NOR

网页「开机 / 待机画面」卡片底部的**抹掉板载 NOR（全部）**按钮发的是 `0A 0A`：
v51 起这会执行一次**整片 1 MB 擦除**（`0xC7`），把开机图、8 张待机图、设置区全部变成 `0xFF`，
然后内存里的设置恢复出厂默认（NOR 保持空白，下次上电自动用默认值）。
固件在等待擦除完成时会持续喂 IWDG —— 1 MB 全片擦除约 1~2 秒，不喂狗会被看门狗复位。

## 刷写

USB 插上，用 WCH-LinkE / WCHISPTool 走 USB 下载，或串口 ISP。刷成砖后的救命通道是板上 `USB_D+` 与 `3.3V` 两个焊盘：**上电瞬间短接**进 ROM ISP。

## 协议（v31）

6 字节定长帧 `[class, sub, b2, b3, b4, b5]`。

| 帧 | 含义 |
|---|---|
| `00 4D ...` | 握手，设备回 `\0MSN02` |
| `00 56 ...` | 版本查询 → `[0x56, major, minor, touch_hi, touch_lo, 0xAA]` |
| `02 00 x0 y0` / `02 01 x1 y1` | 设起点 / 终点（**终点是排他的**） |
| `02 03 07 ...` | 开流：设窗口 + 拉低 CS + 清收流状态 |
| `02 03 0C` / `02 03 0D` | 原样段 / 行程编码段（长度在 `b3:b4`） |
| `02 03 08 ...` | 推一段（长度在 `b3:b4`） |
| `02 03 09 ...` | 收流：flush、抬 CS，**回一个裁决字节** |
| `08 ch ...` | 读 ADC → `[0x08, ch, 0, 0, hi, lo]` |
| `09 01 / 09 02 / 09 03` | NOR 存档：读 / 写 / 擦（16 字节 + CRC32，地址 `0x0FF000`） |
| `0A 00 / 0A 07` | 资产查询 → `[0A, 00, boot_valid, standby_mask, boot_mode, standby_mode, count, dwell_hi, dwell_lo, fw, 0, AA]` |
| `0A 01 kind slot len_hi len_lo` | 开始写一张图（`kind` 0=开机 1=待机），随后紧跟 `len` 个字节像素 → 回 `0x06` |
| `0A 08 len_hi len_lo` | 送一段数据（≤4096 B），**设备把这段真正写进 flash 之后才回 ack**；主机按 1 KB 一窗推，永远不会比设备快 |
| `0A 02` | 放弃本次写入 |
| `0A 03 crc32(4B)` | 提交：设备校验 CRC，对上才写文件头 → 回 `0x06` / `0x15` |
| `0A 04 kind slot` | 立刻把某张图画到屏上（预览） |
| `0A 05 kind slot` | 擦掉某张图 |
| `0A 06 boot stdby count dwell` | 存显示设置（开机画不画图 / 待机模式 / 轮播张数 / 每张秒数） |

像素字节序是 RGB565 小端。

**裁决字节**：每次 `02 03 09` 设备回 `0x06`（本帧像素数对得上窗口）或 `0x15`（少收了）。主机据此决定重发，也天然限速——不会把接收环挤爆。

## 资产：开机画面与待机画面（v32）

板载 1 MB NOR 不只用来看容量，它现在存用户自己的画面，**不连上位机也生效**：

```
0x000000  开机画面   1 槽（32 KB）
0x010000  待机画面   8 槽（0x010000 + n * 0x8000）
0x0FF000  设置区     32 字节（magic + 版本 + 模式 + CRC32）
```

- 每槽开头 20 字节头：`'MSA1' | w(2) | h(2) | fmt(1) | flags(1) | len(4) | crc32(4) | pad(2)`，后面是 RGB565 小端像素（160×80 = 25 600 字节）。
- 写一张图：`0A 01`（清空槽位）→ 反复 `0A 08` + 1 KB 数据（每窗等 ack）→ `0A 03` 带 CRC32。
- 资产写入带 1 秒看门狗：主机半路消失，设备会自己作废这次写入，不会卡成哑巴。设备先擦干净（7 个 4 K 扇区），**数据写完才写文件头**，所以中途断电的槽仍然算“空”，不会画出半张图。
- 容量：一张图 25 KB，开机 1 张 + 待机 8 张 = 225 KB，1 MB 里绰绰有余。
- 屏上显示时是边从 NOR 读边推面板，4 行一批（总线是屏和 flash 共用的，必须 DMA 传完再去读下一批）。

**待机模式的四种画法**（`standby_mode`）：

| 值 | 画什么 |
|---|---|
| 0 | 黑屏 |
| 1 | 四角各一个 8×8 方块，白 ↔ 黄 约每秒交替（默认） |
| 2 | 图片轮播：`standby_count` 张，每张停留 `dwell` 秒 |
| 3 / 4 | 弹球 / 呼吸灯（预留，尚未实现） |

**开机画面**：`boot_mode=1` 时上电先把 NOR 里的图画出来，停留到主机发第一帧；`boot_mode=0` 直接进待机画面。

## 显示与待机

**开机画面停留**：设置区里的 `boot_hold`（1..60 秒，默认 4），画完开机图后安静这么多秒才切到待机画面；上位机断开时仍按 4 秒回待机。

- 待机画面：**四个角各一个 8×8 方块，白 ↔ 黄 约每秒交替一次**；主机一发帧立即让位。
- 上位机断开（或连续 4 秒没发帧）→ 自动回到待机画面，不会停在最后一帧上。
- 除了这四个方块，屏幕上不画任何调试标记；**调试模式已彻底移除**（它会跟看门狗互相干扰，而且曾经把配置写进 NOR 引发过卡死）。

## 看门狗

- IWDG 在 `main()` 里启动后不可关闭，超时约 1.6 s，主循环每轮喂一次。
- 所有异常向量都指向 `trap_loop`（紧循环），所以 HardFault 等异常等价于“1.6 秒后自动重启”，不会永久卡死。
- flash 擦写期间未喂狗：单页写/4 K 擦只有几十毫秒，安全；将来做大量资产写入时需要在擦写循环里补喂。
