# MSU2_MINI 固件

这是一块 0.96 英寸彩色屏桌面终端的自研固件。原厂固件功能封闭、没有公开协议，本仓库从零实现了完整的显示、资产存储、免拆自更新和触摸上报，并配套一套串口协议，供上位机（[Open_MSU2_MINI_Console](https://github.com/hsushjk/Open_MSU2_MINI_Console)）驱动。

当前版本 **1.0.9**，对应硬件标识 `MSU2M-24Q3`。

## 硬件

| 项目 | 参数 |
| --- | --- |
| 主控 | CH32X033F8P6，RV32IMAC，48 MHz（内部 HSI，无外部晶振） |
| 程序存储 | 内部 flash 64 KB，应用镜像限制在 60 KB（`0x0000`–`0xF000`），末尾 4 KB 保留 |
| 内存 | 20 KB SRAM |
| 外部存储 | P25D80H，1 MB SPI NOR |
| 显示屏 | ST7735S，160×80，RGB565，SPI 模式 3，24 MHz |
| 触摸 | 单电极，ADC 通道 9 采样 |
| USB | CH32 内置 USB 全速设备，CDC-ACM 双接口，VID `1A86` / PID `FE0D` |

引脚分配与电气约束见 [Open_MSU2_MINI](https://github.com/hsushjk/Open_MSU2_MINI) 仓库。需要注意两处板级复用：

- PA6 同时是屏的 D/C 与 NOR 的 MISO，读写 NOR 前必须先把屏流收尾、把 CS 抬高。
- 屏 CS 是 PC3，复位是 PA0；PA9 没有负载。

## 功能

- **推流显示**：整帧直写、16×16 分块差分、RLE 行程编码三种形态，按帧自适应选择。
- **写入核对**：设备为每个 16×16 块维护“实际画上屏”的签名，主机发完一帧后询问，设备回 50 位掩码，主机只补发没画对的块。
- **资产**：1 张开机画面 + 16 张待机画面存于板载 NOR，支持裸 RGB565 与 RLE 两种格式，写入带长度与 CRC32 校验。
- **自更新**：镜像先写入 NOR 暂存区，校验通过后由设备在 RAM 中搬运到内部 flash，无需拆机或短接。
- **待机**：黑屏、四角方块、图片轮播（含交叉淡入）、弹球四种模式。
- **触摸**：ADC 采样并做去抖，读数为原始量，具体手势判定由上位机完成。
- **失效保护**：独立看门狗、流式写入超时回收、复位原因面包屑、内部 flash 写入令牌。

## 构建

需要 RISC-V 工具链（xpack `riscv-none-elf-gcc` 14.2 及以上），默认路径可用环境变量 `RISCV_TOOLCHAIN` 覆盖：

```powershell
$env:RISCV_TOOLCHAIN = "C:\path\to\riscv-none-elf-gcc\bin"
.\build.ps1
```

产物在 `build\` 下：`msu2_proto_fw.elf`、`msu2_proto_fw.bin`、`msu2_proto_fw.hex`。编译选项为 `-march=rv32imac_zicsr -mabi=ilp32 -Os`，当前镜像约 20 KB 代码、14 KB 静态内存。

## 刷写

两种方式：

1. **ISP**：断电，短接 `USB_D+` 与 `3.3V` 焊盘后上电，用 WCHISPTool 选择 CH32X033 写入 `build\msu2_proto_fw.hex`。
2. **OTA**：设备正常运行时，通过上位机把 HEX 交给设备写入 NOR 暂存区，再触发搬运。上位机命令：

```bash
python msu2_mini.py --port <串口> --flash build\msu2_proto_fw.hex
```

## NOR 分区

| 地址 | 用途 | 大小 |
| --- | --- | --- |
| `0x000000` | 开机画面，1 槽 | 32 KB |
| `0x008000` | 待机画面，16 槽，每槽 `0x6800` | 416 KB |
| `0x080000` | 应用镜像暂存（OTA） | 128 KB |
| `0x0A0000` | 更新标志 | 4 KB |
| `0x0FF000` | 设置区 | 32 B |

资产槽首部 20 字节：

```
'M''S''A''1' | w(2) | h(2) | fmt(1) | flags(1) | len(4) | crc32(4) | pad(2)
```

`fmt=0` 为裸 RGB565（高字节在前，固定 25 600 字节），`fmt=1` 为 RLE（3 字节一包 `[cnt, hi, lo]`）。数据写完才写槽头，因此写入中途断电的槽仍然视为空。

应用镜像暂存区首部 16 字节：magic `MSU2`、标志位、长度、CRC32。

## 串口协议

帧长固定 6 字节：`[class, sub, b2, b3, b4, b5]`。两处 16 位立即数的组合方式为 `a = b2:b3`、`b = b4:b5`（高字节在前）。设备不回显命令，只在需要时回固定长度的结果。

### 握手与版本

设备空闲时周期性发送 6 字节 `00 4F 50 4D 53 55`（`\0OPMSU`）。主机收到后回 `00 4F 4B 4D 53 55`（`\0OKMSU`），设备原样回显一次。

版本查询为 `00 56 00 00 00 00`，设备回 7 字节：

```
56 | 主版本 | 次版本 | 修订 | 触摸高 | 触摸低 | AA
```

### 显示（class `0x02`、`0x04`）

| 帧 | 含义 |
| --- | --- |
| `02 00 x0 y0` | 设置窗口起点，超出屏幕的坐标被钳住 |
| `02 01 x1 y1` | 设置窗口终点（不含） |
| `02 03 00 c_hi c_lo` | 纯色填充当前窗口 |
| `02 03 04 c_hi c_lo` | 同上 |
| `02 03 07 00 00` | 开始流式写入，设置窗口并把屏 CS 拉低 |
| `02 03 08 00 len_hi len_lo` | 推一段像素数据 |
| `02 03 0C 00 len_hi len_lo` | 推一段原样数据（先刷新已缓冲的段） |
| `02 03 0D 00 len_hi len_lo` | 推一段 RLE 数据 |
| `02 03 09 00 00` | 结束本帧 |
| `02 04 byte byte byte byte` | 用 4 字节图案铺满 256 字节段缓冲 |
| `04 idx b2 b3 b4 b5` | 写段缓冲的 `idx*4` 起 4 字节 |

帧结束指令会让设备给出 1 字节裁决：`0x06` 表示收到的像素数与窗口一致，`0x15` 表示不足或超出。主机据此决定是否补发。

### 资产与设置（class `0x0A`）

| 子命令 | 含义 |
| --- | --- |
| `00` / `07` | 查询资产状态，回 14 字节（槽位掩码、开机/待机模式、张数、停留秒数、固件主版本、开机停留秒数） |
| `01 kind idx len_hi len_lo` | 开始写资产；`kind` 最高位为 1 表示 RLE |
| `08 len_hi len_lo` | 送来一段资产数据，收满回 ack |
| `09` | 结束本段 |
| `02` | 放弃本次写入 |
| `03 crc32` | 提交，CRC 校验通过才落槽头 |
| `04 kind idx` | 立即显示某张图（预览） |
| `05 kind idx` | 擦除某槽 |
| `06 boot standby count dwell` | 存设置 |
| `0A A5 5A 00 00` | 抹掉整片 NOR（恢复出厂，需要令牌） |
| `0B` | 读开机自检结果位图 |
| `0C addr(3) len` | 读 NOR，单次最多 48 字节 |
| `0D` | 读复位面包屑，回 8 字节（阶段码、启动次数、上次阶段、复位原因） |
| `0E kind idx` | 资产回读校验 |
| `0F` | 上次自更新的结果码 |
| `10 n` | 动画步进探针：连跑 n 次待机心跳 |
| `11 <100 字节签名>` | 分块签名核对，设备回 10 字节掩码 |
| `12 01 ...` / `12 02 ...` | 自更新：开始 / 送一窗数据（每窗不超过 2048 字节） |
| `18 kind idx x y` | 把某个槽的图画到指定位置 |

### 自更新（class `0x13`、`0x14`）

| 帧 | 含义 |
| --- | --- |
| `13 00 crc32` | 提交 NOR 暂存区里的镜像，设备重算 CRC 比对 |
| `14 00 A5 5A 00 00` | 触发搬运：校验镜像后写入内部 flash 并复位 |

`0x14` 有三个前置条件：帧里必须带 `A5 5A` 令牌、本次上电已经成功执行过 `0x13`、且当前不在任何收流状态。任一不满足时设备回 `14 00 15 FE 00 00` 并保持原样。

### 其他

| 帧 | 含义 |
| --- | --- |
| `08 ch 00 00 00 00` | 读 ADC 通道，回 `08 ch 00 00 hi lo` |

## 设置项

| 字段 | 取值 |
| --- | --- |
| 开机模式 | 0 不画；1 画 NOR 里的开机画面 |
| 待机模式 | 0 黑屏；1 四角方块；2 图片轮播；3 弹球 |
| 轮播张数 | 1–16 |
| 每张停留 | 秒 |
| 开机画面停留 | 1–60 秒，默认 3 秒 |

## 稳定性设计

设备没有 A/B 双区，所有保护都体现在“宁可不动，也不能写坏”上：

- **内部 flash 写入令牌**：只有先成功提交镜像、并且帧里带 `A5 5A`，才允许搬运。命令流与像素流共用一条串口，帧一旦被截断，后续字节会被当作命令解析；没有令牌时，图像数据里偶然出现的 `0A 14` 会把应用区擦掉一半。
- **先校验后搬运**：搬运前在 RAM 中逐字节比对镜像头与 CRC，再按 1 KB 页擦写并逐页读回，失败则恢复中断与引脚状态，让当前固件继续运行。
- **流式写入超时**：像素、资产、OTA、签名四类收流都在主循环里按圈数计时，长时间没有新数据就丢弃本次会话，回到空闲。
- **半帧对齐**：完全空闲时若手上残留 1–5 字节且 100 ms 没有新数据，整段丢弃，下一帧从干净边界重新对齐。
- **复位面包屑**：关键阶段写入 RAM 底部不初始化的区域，异常复位后仍可读，用于判断上次死在哪一步。
- **独立看门狗**：主循环持续喂狗，任何一处卡死都会复位。

## 已知限制

- 内部 flash 没有 A/B 双区，搬运过程中断电需要 ISP 重新刷写。
- 触摸只上报原始 ADC 值，没有硬件滤波，阈值与手势由上位机判定。
- 推流速率受设备主循环按 64 字节一包消费的限制，整帧上限约 10 fps。
- 屏与 NOR 共用 PA6，任何 NOR 访问都会打断正在进行的屏流。
