# Open_MSU2_MINI_FW

MSU2_MINI 小屏（CH32X033F8P6 + P25D80H + ST7735S 160×80）的自研固件 **v1.0.2**：不基于原厂固件、不链接 WCH 库，`-nostdlib` 从 `_start` 起手写，实现 USB CDC 流式刷屏、NOR 图像资产、触摸采样、开机/待机动画、免拆自更新和一套自诊断命令。

## 关键特性

- **6 字节定长帧**，每条命令一句话；收流完成回 **1 字节裁决**（`0x06` 对 / `0x15` 缺），主机据此整帧重发，不需要长度/序号/校验字段。
- **160×80 RGB565 直写流**：分段缓冲 + RLE 压缩段 + DMA 突发，终到点排他，窗口像素数对不上立刻报缺。
- **板载 1 MB NOR 资产**：开机图 1 槽 + 待机图 16 槽 + 应用镜像暂存 + 设置区，写进 NOR 就断电生效，不依赖上位机。
- **免拆 OTA**：NOR 暂存 → CRC 提交 → RAM 里先整段重算 CRC、再体检内部 flash 的 `0xF000` 页 → 擦写搬运并读回校验 → 复位。任一步不过都不动内部 flash；CRC 预检不过连擦除都不会发生。
- **三道保险**：接收环满只 NAK 不丢字节；段超时 / 断流 / 字节预算三重放弃；IWDG ≈1.6 s 兜底。
- **现场可读的故障现场**：`.noinit` 复位面包屑（阶段码 + 复位次数）+ 异常整屏色卡 + 开机五项自检。
- **自检命令集**：NOR 回读、资产 CRC 回读、50 块分块签名核对、动画步进探针、内部 flash `0xF000` 页擦写体检、JEDEC ID / 应用起始读回、任意槽贴图。

| 版本 | 要点 |
| --- | --- |
| **v1.0.2** | `standby_count` 真正生效：待机图片轮播只在前 `N` 个槽之间循环（`N` = 1..16，默认 16 = 全部槽）；`0A 06` 的 `count` 钳到 1..16 |
| v1.0.1 | 体检页挪到 `0xF000`（链接期断言兜底）；OTA 擦前整段 CRC 预检；上传窗口 0.4 s 自愈；待机动画改非阻塞计数；触摸加中值 + 滞回；新增 `0A 15..18` 四条自检命令 |
| v1.0.0 | 首个公开自研版本：USB CDC 流式刷屏、NOR 资产、免拆 OTA、五项自检 |

**v1.0.2 变更摘要**（`FW_VER_MINOR` 1 → 2，只更新固件，上位机仍是 v1.0.0）：

1. 待机图片轮播上限改为按 `standby_count` 走：`standby_limit()` 取 1..16 的有效内存值，异常时退回 `STANDBY_SLOTS`（16 = 全部槽），默认行为与 v1.0.1 完全一致。
2. `next_valid_slot()` 只在前 N 个槽里找图；张数改小后旧索引越界（`>= N`）时从槽 0 重扫，回落到第一个有效槽，不会停在越界槽上把画面留空。
3. `0A 06` 写入的 `count` 钳到 1..16（0 → 1，>16 → 16），此前上限是 8。

**v1.0.1 变更摘要**（`FW_VER_MINOR` 0 → 1）：

1. 新增 `0A 15`（NOR JEDEC ID + 应用起始 16 B）、`0A 16`（待机动画步进探针）、`0A 17`（`0xF000` 页擦写体检，回原始码）、`0A 18`（把任意槽的图画到屏上任意位置，带裁剪）。
2. 内部 flash 体检页从 `0x7000` 挪到 `0xF000`；`link.ld` 增加断言，应用镜像超过 `0xF000` 直接**链接失败**，从构建期保证体检页不踩活代码。
3. `update_apply()` 在解锁 / 擦除**之前**用 `ram_nor_crc()` 重算 NOR 镜像整段 CRC，与镜像头不符时 `g_up_result = 5` 并直接返回，内部 flash 零写入。
4. OTA 上传窗口空闲阈值从 4 000 000 圈（≈1 小时）改为 `UP_IDLE_LIMIT` 400 圈（≈0.4 s），作废时主动回 `0A 12 15`。
5. 待机闪烁不再用阻塞 `delay_ms(1)` 循环，改成主循环计数 `standby_wait`（模式 1 约 1 s、模式 2 按 `dwell`、模式 3 每 20 圈一步），等待期间命令照常处理。
6. 触摸读数加 `adc_filtered()`：每通道 3 拍滑窗中值 + 8 LSB 滞回，`class 0x08` 回包长度不变。

版本号从 v1.0.0 起统一重置：当时固件与上位机同号；v1.0.1 / v1.0.2 只更新固件，上位机仍是 v1.0.0。旧文档里的 v28 / v31 / v60 / v81 只是历史演进编号，不再是“当前版本”。

### 引脚

| 信号 | 引脚 | 去向 |
| --- | --- | --- |
| SPI_SCLK | PA5 | U2.CLK + J1.6 |
| SPI_MOSI | PA7 | U2.DI + J1.5 |
| SPI_MISO / LCD_DC | **PA6** | U2.DO + J1.4（一脚两用，见“已知限制”） |
| CS_Flash | PB7 | U2.CS# |
| CS_LCD | PC3 | J1.8 |

- **JP1 / JP2 / JP3 未焊接，暂不支持**：它们与屏共用 SPI，且 JP1 的 I2C 与 SWD 复用，接上就没调试口。
- **救砖焊盘**：板上 `USB_D+` 与 `3.3V` 两个焊盘**先短接再上电**，可强制进入 ROM ISP（详见下文“救砖”）。
- 屏命令与 flash 访问必须严格串行（PA6 共用），固件里所有 NOR 操作前后都会切换 PA6 方向。

## 构建

需要：`riscv-none-elf-gcc` 工具链（xPack 14.2.0 已验证）、Node.js（跑 `hexfix.js`）、Windows PowerShell。

```powershell
# 交付固件（proto 变体）
.\build.ps1 -Variant proto

# 清理后重编 / 顺便导出反汇编
.\build.ps1 -Variant proto -Clean
.\build.ps1 -Variant proto -Disasm
```

工具链路径可用环境变量覆盖，默认值如下：

```powershell
$env:RISCV_TOOLCHAIN = 'C:\Users\hsush\Tools\riscv\xpack\xpack-riscv-none-elf-gcc-14.2.0-3\bin'
```

| 项 | 说明 |
| --- | --- |
| 默认 Variant | `bars`（点屏彩条）；日常只会用 `proto` |
| 其它 Variant | `erase, dump, probe, usb, stage, csrtest, min, mincsr, stage_nousb, stage_usb, ladder, usbstage, usbstep, usbregs, usbforce, host, protorx, ping, direct, isrmin, poll, timed, all`，各自对应一个 `src/main_*.c` 实验程序，只用于硬件调试 |
| 编译选项 | `-march=rv32imac_zicsr -mabi=ilp32 -Os -ffreestanding -nostdlib -nostartfiles -Wl,--gc-sections` |
| 产物 | `build/firmware.elf`、`build/msu2_proto_fw.hex`、`build/msu2_proto_fw.bin` |

**退出码 1 是假象**：GCC 会往 stderr 打诊断信息，PowerShell 会把它当错误，脚本经常以退出码 1 结束但产物正常。判断标准是输出里有没有 `error:`，以及最后一行是否打印出

```
msu2_proto_fw.hex: 50884 bytes, msu2_proto_fw.bin: 18084 bytes
```

构建末尾会自动执行 `node tools/hexfix.js <hex> <hex> <bin>`：把 HEX 段间空洞填成 `0xFF`、换行统一成 CRLF。不做这一步，WCHISPStudio 可能转换失败或烧完不启动。

## 刷写

### 路线 A：USB ROM ISP（第一次烧录 / 救砖）

1. 装 [WCHISPTool](https://www.wch.cn/downloads/WCHISPTool_Setup_exe.html)，本机路径 `C:\WCH\WCHISPTool\WchIspStudio.exe`。
2. 芯片选 **CH32X033**（列表里只有 CH32X035 同系列项也可以）。
3. **按住短接 `USB_D+` 与 `3.3V` 两个焊盘的同时**把板子插进 USB，工具出现 `1a86:xxxx` 引导设备后立刻松开。
4. 选中 `build/msu2_proto_fw.hex`，起始地址 `0x0000`，勾选校验后下载。
5. 拔插一次 USB，上位机应能识别到设备并收到 `\0MSN02`。

裸 `bin` 则从 `0x0000` 起烧；HEX 的地址在记录里，不用填起始地址。烧写过程中不要拔线，半写状态重进 ISP 完整重烧即可恢复。

### 路线 B：OTA（免拆升级，v1.0.0 起）

主机把 Intel HEX 解析成裸 bin，全程通过 `class 0x0A` / `0x13` / `0x14` 完成：

| 步 | 命令 | 作用 |
| --- | --- | --- |
| 1 | `0A 12 01 00 len_hi len_lo` | 擦 NOR `0x080000` 区并登记镜像长度（1..48000） |
| 2 | `0A 12 02 00 wl_hi wl_lo` + 数据 | 分窗写入，每窗 ≤2048 B，收满回 `0A 12 06`；窗口半开空转 ≈0.4 s 作废，主动回 `0A 12 15 00 00 00` |
| 3 | `13 00 crc0 crc1 crc2 crc3` | 提交 CRC32：NOR 读回重算对上才写 16 B 镜像头并置 VALID |
| 4 | `14 00 00 00 00 00` | 置“请更新”标志；80 ms 后先整段 CRC 预检、再体检 `0xF000` 页，都通过才擦写搬运并复位 |

镜像落点（NOR，头 16 B）：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | `'M''S''U''2'` |
| 4 | 1 | flags：bit0 = 镜像有效（bit1 在代码里有定义但从未写入） |
| 5 | 1 | 保留（0） |
| 6 | 4 | len（小端，必须 256 的整数倍、≤48000） |
| 10 | 4 | crc32（小端） |
| 14 | 2 | 保留 |
| 16 | len | 镜像本体 |

镜像头的 flags 实际只用 bit0；真正的“请更新”是 `0x0A0000` 扇区里的 `0xA5` 标志（见 NOR 分区表），所以置 / 清这个标志不需要碰镜像头，擦写镜像头也不会误触发升级。

搬运结果用 `0A 0F`（上次结果）或 `0A 23` 读 `g_up_result`（`0A 23` 第 3 字节是本次体检成败，第 4 字节才是上次搬运的 `g_up_result`）：

| 值 | 含义 |
| --- | --- |
| 0 | 成功（随后自动复位） |
| 1 | 镜像头 magic 不对 |
| 2 | 长度非法（0 / >48000 / 非 256 整倍） |
| 3 | 体检失败（擦写 `0xF000` 页读回不一致，**内部 flash 一点没动**） |
| 4 | 搬运后逐字节读回校验失败 |
| 5 | 整段 CRC 与镜像头不符（v1.0.1 起新增，**内部 flash 一字节没动**） |

v1.0.1 起，`update_apply()` 在读头之后、解锁内部 flash **之前**先跑 `ram_nor_crc()`：它本身在 `.ramfunc` 里，按 256 B 分块从 NOR 读镜像，用逐位算法（poly `0xEDB88320`）重算整段 CRC32；结果与头里的 crc32 不一致就置 `g_up_result = 5` 直接返回，**擦除一次都不会发生**。体检页也从 `0x7000` 挪到了 `0xF000`（`IFLASH_PROBE_ADDR`，应用区止于 `0xEFFF`），并且 `link.ld` 里加了

```ld
ASSERT(LOADADDR(.data) + SIZEOF(.data) <= 0xF000,
       "application image overruns the 0xF000 internal-flash probe page")
```

固件一旦超过这个边界就**链接失败**，不会产出“能烧但会把自己体检页踩掉”的镜像。

内部 flash 编程必须走 WCH 官方页缓冲序列：`KEYR`/`MODEKEYR` 解锁 → `CTLR` 置 `PAGE_PG`(bit16) + `BUF_RST`(bit19) → 64 次 `BUF_LOAD`(bit18) 写满 256 B → `STRT`(bit6) 启动 → 轮询 `STATR.BSY`，地址一律用 `0x08000000` 别名。**半字直写在这颗片上无效**。

搬运和 CRC 预检用的整段代码都在 `.ramfunc`（链接进 `.data`，启动时拷到 RAM）：擦掉应用区以后仍能执行，IWDG 由 RAM 里的 `ram_iwdg()` 喂。

## NOR 分区表（1 MB）

| 地址 | 大小 | 用途 |
| --- | --- | --- |
| `0x000000` | 0x6800（26 KB） | **开机图** 1 槽（kind 0 / slot 0；槽后到 `0x008000` 留空） |
| `0x008000 + idx*0x6800` | 0x6800 × 16 | **待机图** 16 槽（idx 0..15），末端 `0x070000` |
| `0x080000` | 16 B + ≤48000 B | OTA 应用镜像暂存（头 16 B + 镜像） |
| `0x0A0000` | 4 KB | “请更新”标志扇区（单独一扇，写它不碰镜像头） |
| `0x0FF000` | 32 B | 设置区（`CFG_MAGIC 'MS2S'` + settings_t） |

每个图像槽：**20 B 头 + 25 600 B RGB565 小端数据**。

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 魔数 `'MSA1'`（`0x3141534D`） |
| 4 | 2 | 宽 w（**小端**，固定 160） |
| 6 | 2 | 高 h（**小端**，固定 80） |
| 8 | 1 | 像素格式：0 = RGB565（其它值判为无效） |
| 9 | 1 | flags（0） |
| 10 | 4 | 数据长度 len（**小端**，固定 25 600） |
| 14 | 4 | 数据 crc32（**小端**） |
| 18 | 2 | pad |

槽头里的多字节量是**小端**，和串口协议的大端相反，写图时别搞混。一个槽 20 B 头 + 25 600 B 数据 = 25 620 B，槽容量 `0x6800`，余下留白。

**数据写完才写头**：上一版头先被擦掉，写完 25 600 B 数据再补 20 B 头，所以断电最多丢新图，不会出现“头合法但数据是半截”的图。槽是否有效由 `asset_valid()` 判（头 + CRC），空槽（`0xFF…`）在待机轮播里直接跳过。

## 串口协议

### 物理层

| 项 | 值 |
| --- | --- |
| USB | 全速设备，**只声明 CDC-ACM 双接口**（不再声明 HID；原厂那个 HID 接口没有端点，Windows 拉 HID 驱动必失败） |
| VID / PID | `0x1A86` / `0xFE0D`（注意末位与原厂 `0xFE0C` 不同，可据此区分自研/原厂） |
| 端点 | 接口0 控制 EP `0x81` 中断 8 B；接口1 数据 EP `0x02` OUT / `0x83` IN，各 64 B |
| 描述符 | bcdUSB `0x0110`，EP0 64 B；字符串 `MSU2` / `MSU2_MINI` / `MSU2M24Q3001` |
| 波特率 | 任意（CDC 忽略，上位机默认按 19200 打开也无妨） |

### 帧格式

```
[class, sub, b2, b3, b4, b5]     固定 6 字节
```

多字节量（坐标、长度、CRC）一律**大端**；颜色 RGB565 **大端**。固件不解析长度也不做转义，收到 6 字节就分派。

### 设备主动发出的包

| 包 | 时机 | 内容 |
| --- | --- | --- |
| 问候 | 上电、上位机每次打开端口（`SET_CONTROL_LINE_STATE` 0x22 后重新武装）、待机期每 ~50 ms、静默 120000 轮后补发一次 | `00 4D 53 4E 30 32` = `\0MSN02` |
| 帧裁决 | 每收完一次 `02 03 09`（收流） | 1 字节：`0x06` 像素数对上 / `0x15` 少了 |
| SysTick 自检 | 开机一次 | `77 lo hi 00 00 AA`（`delay_ms(10)` 的 tick 差 / 48000，正常约 480000） |

主机必须回 `00 4D 53 4E 43 4E`（`\0MSNCN`）才算握手完成（固件会原样回显这 6 字节）。

### class 0x00 系统

| sub | 名称 | 请求 | 回包 |
| --- | --- | --- | --- |
| `0x4D` | 握手应答 | `00 4D 53 4E 43 4E` | 原样回显 6 B，置 connected |
| `0x56` | 版本查询 | `00 56 00 00 00 00` | `56 MM mm TH TL AA`（MM/mm = 主/次版本，TH/TL = 触摸 ADC 值） |

### class 0x02 显示

坐标先设：`sub 0` 起点 `(x0,y0)`，`sub 1` 终点 `(x1,y1)`，**终点排他**（`x1-x0` 才是宽）。

| sub | 名称 | 字节 | 说明 |
| --- | --- | --- | --- |
| `0x00` | 设起点 | `b2b3 = x0`，`b4b5 = y0` | 大端 |
| `0x01` | 设终点 | `b2b3 = x1`，`b4b5 = y1` | 排他 |
| `0x02` | 设页号 | `b2 = page` | 当前固件仅记录 |
| `0x03` | 绘图操作 | `b2 = 操作码` | 见下表 |
| `0x04` | 设填充单元 | `b2..b5` | 4 字节循环铺满 256 B 段 |

`sub 0x03` 操作码：

| 操作码 | 作用 | 参数 |
| --- | --- | --- |
| `0x00` / `0x04` | 矩形填充 | 颜色 = `(b3<<8)\|b4`，区域 = 起点..终点 |
| `0x07` | 开流 | 记下窗口 `win_px = (x1-x0)*(y1-y0)`，清像素计数，屏进直写 |
| `0x08` | 送 256 B 段 | 整个 `seg[256]` 刷进窗口 |
| `0x0C` | 原样段 | 长度 = `(b3<<8)\|b4`（上限 8192），后续字节原样进流 |
| `0x0D` | 压缩段 | 长度同上；`b5=1` 时走 RLE |
| `0x09` | 收流 | flush 剩余段、结束直写、回 1 字节裁决 |

- 窗口像素数用**字节数折算**：`frame_px += 段长/2`。收流时 `frame_px == win_px` 回 `0x06`，否则回 `0x15`，主机整帧重发。
- RLE 格式：每 3 字节一组 `[像素数, 高字节, 低字节]`，展开成 `count` 个相同 RGB565 像素；展开后超过分段缓冲就地 flush，所以 `count` 可以跨 512 B 边界。

### class 0x04 段内 BULK

| 帧 | 作用 |
| --- | --- |
| `04 idx b0 b1 b2 b3` | `seg[idx*4 .. idx*4+3] = b0..b3`（仅当 `idx*4+4 <= 256`） |

一条帧搬 4 字节，是刷屏时最热的路径；`idx` 由主机按段内偏移给。

### class 0x08 ADC / 触摸

| 帧 | 回包 |
| --- | --- |
| `08 ch 00 00 00 00` | `08 ch 00 00 hi lo`（`v = (hi<<8)\|lo`） |

`ch 9` = 触摸电极（TKey 注入通道模式：`ADC_CTLR1 |= 1<<24` 打开 TKEN，`IDATAR1=0x70`、`RDATAR=0x40`，等 `EOC|JEOC` 后取上一拍值）。`ch 15` = 内部参考/心跳采样。

触摸类读数（`class 0x08`）统一走 `adc_filtered()`：每通道保留最近 3 拍，取中值去掉单点尖峰，再叠 8 LSB 滞回（手指不动时基准在 3900 上下抖，没有滞回会每次 ±1 跳）；换通道时历史清零，头两拍还没有中值可算、原样返回。一条命令只取一个采样——`adc_read()` 是“取上一拍已完成的结果、启动下一拍、立即返回”的非阻塞写法，绝不等待。v1.0.1 起回包长度仍是 6 字节，主机侧不用改。版本查询（`0x56` 的 TH/TL）与开机自检仍是裸 `adc_read(9)` 单次采样，不带滤波。

### class 0x0A 资产 / 自更新 / 诊断

| sub | 名称 | 请求字节 | 回包 |
| --- | --- | --- | --- |
| `00` / `07` | 查询状态 | — | 14 B：`0A sub boot_valid mask_lo mask_hi boot_mode standby_mode count dwell_hi dwell_lo fw_major boot_hold 00 AA` |
| `01` | 开始写图 | `b2=kind`（0 开机/1 待机），`b3=slot`，`b4b5=len` | `0A 01 ok`（`ok`: 0x06 接受 / 0x15 拒绝） |
| `08` | 送一段 | `b4b5=长度`（0 或 >4096 按 4096） | 收满回 `0A 08 06` |
| `02` | 放弃本次写 | — | `0A 02 06` |
| `03` | 提交 CRC32 | `b2..b5 = crc` | `0A 03 06/15`（对上才写 16 B 镜像头） |
| `04` | 预览槽 | `b2=kind`，`b3=slot` | `0A 04 06/15` |
| `05` | 擦除槽 | `b2=kind`，`b3=slot` | `0A 05 06` |
| `06` | 存设置 | `b2=boot_mode`，`b3=standby_mode`，`b4=count`（1..16，超出自动钳住），`b5=dwell` | `0A 06 06` |
| `09` | 开机停留秒数 | `b2 = 1..60` | `0A 09 06 secs 00 00` |
| `0A` | 整片抹 NOR | — | `0A 0A 06`（擦完恢复默认设置） |
| `0B` | 开机自检结果 | — | `0A 0B rep 00 00 00`（bit0 FLASH/bit1 TOUCH/bit2 LCD/bit3 USB/bit4 CFG） |
| `0C` | 读 NOR | `b2b3b4 = addr(24 位)`，`b5 = 1..48` | `0A 0C n <n 字节> AA` |
| `0D` | 复位面包屑 | — | `0A 0D stage boots_lo boots_hi AA` |
| `0E` | 资产回读校验 | `b2=kind`，`b3=slot` | `0A 0E 06/15 crc_lo crc_hi AA` |
| `0F` | 上次自更新结果 | — | `0A 0F code 00 00 00`（`g_up_result`） |
| `10` | 动画步进探针 | `b2 = 1..40 步` | `0A 10 06 n 00 AA` |
| `11` | 分块签名核对 | 帧后紧跟 100 B 签名（50 块 × u16 小端） | 10 B：`0A 11 00 … 00 AA`，`[2+bit]` 置位 = 该块没对上 |
| `12` | OTA 写镜像 | `b2=01` 开始（`b4b5=len`）；`b2=02` 分窗（`b4b5=wl`，≤2048） | 开始 `0A 12 06/15`；分窗收满 `0A 12 06`；半开窗口空转 ≈0.4 s 回 `0A 12 15` |
| `15` | 自检扩展：JEDEC ID + 应用起始 | — | 23 B：`0A 15 13 <id0 id1 id2> <应用起始 16 B> AA`（`0x13` = 后续 19 字节） |
| `16` | 待机动画步进探针 | `b2 = 1..40 步`（0 按 1） | `0A 16 06 steps cad_hi cad_lo`（`cad` = 当前动画节拍，单位“主循环圈数/帧”） |
| `17` | 内部 flash `0xF000` 页体检 | — | `0A 17 06/15 raw 00 00`（`raw`：0 成功 / 1 擦后读回不是 `0xFF` / 2 写后读回不一致） |
| `18` | 贴图到屏幕 | `b2=kind`（0 开机 / 1 待机），`b3=slot`，`b4=x`、`b5=y`（有符号 int8） | `0A 18 06/15 00 00 00` |
| `23` | 内部 flash 写序列体检 | — | `0A 23 code g_up_result 00 00`（`code` = 本次体检 06/15，第 4 字节是上次搬运的 `g_up_result`） |
| `24` | 体检区读回 | — | 12 B：`0A 24 08 <0x0800F000 起 8 字节> AA` |

新增四条命令的细节：

- `0A 15`：这 16 字节不是“自检位图”，而是 `0x08000000` 起应用区最前面的 16 B（向量表开头：初始 SP、复位 / NMI / HardFault 入口），用来核对烧进去的镜像开头；NOR 的 JEDEC ID 正常是 `85 60 14`。
- `0A 16`：**不报毫秒**。这颗片的 SysTick 分频 / 方向不可靠，工程约定时间基准只用主循环迭代计数或 `delay_ms()`，所以第 4-5 字节是“主循环圈数/帧”：空闲时一圈末尾 `delay_ms(1)`，1 圈 ≈ 1 ms。`N` 步是同步真跑 N 次 `standby_tick()`（每步喂狗），毫秒耗时请上位机对回包做往返计时。
- `0A 17`：只体检内部 flash 的 `0xF000` 页，不碰应用区；第 3 字节是 `update_probe()` 的原始码，便于区分“擦不干净”和“写不进”。注意 `0A 23` 的第 4 字节是 `g_up_result`（上次搬运结果），不是本次体检原始码——要看原始码用 `0A 17`。
- `0A 18`：先 `lcd_raw_idle()` 收尾屏流并清 `standby_mode`（画上去的图不会一秒后被待机动画盖掉）；`x/y` 是有符号 int8，可以给负偏移，只画与 160×80 的交集（越界自动裁剪；完全在屏外时回 `06` 但什么也不画）；`kind>1`、待机槽号 ≥16 或槽无效回 `15`。

设置字段的取值与钳位（`sub 06`）：

| 字段 | 取值 | 越界处理 |
| --- | --- | --- |
| boot_mode | 0 不画 / 1 显示 NOR 开机图 / 2 开机跑自检并显示结果 | >2 → 0 |
| standby_mode | 0 黑屏 / 1 四角方块闪光 / 2 图片轮播 / 3 Ping-Pong 小球 / 4 预留 | >4 → 1 |
| standby_count | 轮播张数：限定轮播只在前 N 个有效槽之间循环，`N` 取 1..16，默认 16（=全部槽），空槽跳过 | 0 → 1，>16 → 16 |
| dwell | 每张停留秒数 1..60 | 0 → 3 |
| boot_hold | 开机图停留秒数 1..60 | 0 → 4 |

### class 0x13 / 0x14 自更新

| 帧 | 作用 | 回包 |
| --- | --- | --- |
| `13 00 c0 c1 c2 c3` | 提交 NOR 镜像 CRC32 | `13 00 06/15 00 00 00` |
| `14 00 00 00 00 00` | 置更新标志并立即搬运 | 先回 `14 00 06 00 00 00`；80 ms 后先整段 CRC 预检、再体检 `0xF000` 页，通过才擦写；失败回 `14 00 15 <g_up_result> 00 00` 并清标志 |

| class | 状态 |
| --- | --- |
| `0x09` 原厂存档（devcfg） | 不实现，上位机发来无应答（`--selftest` 会提示“设备存档不可用”） |
| `0x03` NOR 页命令 | 不实现，NOR 只通过 `0x0A` 资产/诊断通道访问 |

## 显示、开机与待机

### 开机（`boot_mode`）

| 值 | 行为 |
| --- | --- |
| 0 | 不画，直接进待机画面 |
| 1 | 画 NOR `0x000000` 的开机图，停留 `boot_hold` 秒（1..60）后进待机；图无效则跳过 |
| 2 | 跑五项自检并显示结果，**固定 1.5 秒**后进待机 |

自检项与判据：

| 项 | 判据 |
| --- | --- |
| FLASH | `flash_read_id` 三字节 = `85 60 14` |
| TOUCH | 丢首拍后隔 2 ms 再读 ch9，`100 < v < 4200` |
| LCD | 恒通过（能走到这里说明初始化没卡死） |
| USB | 恒通过 |
| CFG | 设置区能读且魔数对 |

画面不用字库：左侧一列 5 个 10×10 方块（FLASH/TOUCH/LCD/USB/CFG），绿 = 通过、红 = 失败、灰 = 未跑；右侧 20×20 总结果方块，全绿才算全过。

### 待机（`standby_mode`）

断开上位机 **4 秒**进入待机（有开机图时按 `boot_hold` 计时）。

| 值 | 行为 | 步进 |
| --- | --- | --- |
| 0 | 黑屏 | — |
| 1 | 四角 8×8 方块白/琥珀交替（`0xFFFF` / `0xFC80`） | `STANDBY_BLINK_TICKS` = 1000 拍 ≈1 s 翻转 |
| 2 | 图片轮播：只在前 N 个槽（`N` = `standby_count`，1..16，默认 16 = 全部槽）之间循环，槽间 8 步交叉淡入淡出（空槽跳过） | `dwell × 1000` 拍 ≈`dwell` 秒 |
| 3 | Ping-Pong 小球：10×10 方块、13 点拖尾渐暗、撞边换色、随机起点方向 | 20 拍/步 ≈20 ms |
| 4 | 预留（当前画四角白方块后静止） | — |

待机动画由主循环推进：每转一圈 `standby_wait++`，攒够节拍才翻色 / 换图 / 走一步，**不再用 `delay_ms()` 阻塞**——这一圈照样收 USB 字节、喂狗、空闲时补发问候，有数据待处理时不推进动画。待机期间每 50 拍补发一次 `\0MSN02`。开流（`02 03 07`）、写图（`0A 01`）、预览（`0A 04`）、贴图（`0A 18`）会清 `standby_mode` 退出待机，其余命令不会打断待机动画。主机侧实测，改造后串口命令响应中位数约 5 ms（旧版在待机时会卡住主循环：模式 1 约 1 秒，图片模式可到整段 `dwell`）。

## 稳定性设计

### 三道保险

| # | 机制 | 行为 |
| --- | --- | --- |
| 1 | 接收环满 | `rx[1024]` 满时只 NAK 不覆盖，字节一个不丢；主机侧靠重发收敛 |
| 2 | 三重放弃 | ①段内 4000 轮无新字节 → 丢弃本段、结束直写 ②字节预算 `stream_bytes > 40000` → 清空全部会话状态 ③资产半开窗空转 4 000 000 轮 → `asset_abort`；OTA 上传窗口空转 `UP_IDLE_LIMIT` = 400 圈（≈0.4 s）→ 清窗口并主动回 `0A 12 15` |
| 3 | IWDG ≈1.6 s | LSI/16 分频，`flash_wait_ready` 与擦除循环里喂狗，卡死必复位而不是假装在线 |

### 复位面包屑（`.noinit`）

```c
typedef struct { uint32_t magic, stage, boots, aux; } trace_t;   // magic = 0x4D534252 "MSBR"
static volatile trace_t g_trace __attribute__((section(".noinit")));
```

放在 `.noinit`（RAM 底部，启动不清零），掉电才丢。`trace_boot()` 每次启动 `boots++`，主流程各阶段写 `stage`；`0A 0D` 读出来就是“上次死在哪”。

| 阶段码 | 位置 |
| --- | --- |
| 1 | `main()` 开头 |
| 2 | `usb_init()` 完成 |
| 3 | 开机画面 |
| 4 | 主循环 |
| 5 | 收像素 |
| 6 | 写资产 |
| 7 | 淡入淡出 |
| 8 | 整片擦除 NOR |
| 9 | 待机动画 |

### 异常色卡

`trap_handler` 把 `mcause & 0xF` 映射成整屏背景色后死等 IWDG 复位：指令地址未对齐=黑、取指访问错误=红、非法指令=绿、断点=蓝、载入未对齐=黄、载入访问错误=青、存储未对齐=洋红、存储访问错误=白、ecall=橙/粉等。`mcause` 最高位为 1（是中断不是异常）时左上角叠 12×12 白块；`mcause & 0x10` 时再叠一个洋红块。看到整屏纯色即可直接定位异常类型。

## 诊断清单

| 想知道什么 | 用哪条命令 |
| --- | --- |
| 上次停在哪个阶段、复位过几次 | `0A 0D` |
| 开机五项自检结果 | `0A 0B` |
| NOR 任意位置读几个字节 | `0A 0C <24 位地址> <长度>` |
| 某个槽的图还在不在、CRC 对不对 | `0A 0E kind slot` |
| 屏有没有画对（50 块签名） | `0A 11` + 100 B 签名 |
| 动画帧能不能跑满 | `0A 10 <步数>` |
| 待机动画一步要多少圈 | `0A 16 <步数>` |
| 这颗片的内部 flash 能不能自更新 | `0A 17`（本次擦写体检原始码，0 才算过）/ `0A 23`（06/15 + 上次 `g_up_result`） |
| 上次自更新为什么失败 | `0A 0F` |
| 应用区开头 16 B、NOR 的 JEDEC ID | `0A 15` |
| 体检页现在是什么内容 | `0A 24` |
| 把某个槽的图贴到屏上任意位置 | `0A 18 kind slot x y` |
| 计时基准是否正常 | 开机时的 `77 …` 自检帧 |

上位机侧对应 `msu2-console --selftest`，一次性跑链路、触摸、帧、分块签名、面包屑、NOR 抽查、资产 CRC 与动画计时。

## 已知限制

| 限制 | 说明 |
| --- | --- |
| JP1 / JP2 / JP3 不可用 | 未焊接；与屏共用 SPI，JP1 的 I2C 还与 SWD 复用 |
| 背光不可调 | 5 V 经 R1 5.1 Ω 直连，无开关无调光；上位机的“亮度”是主机侧压暗像素 |
| SPI 24 MHz 超屏规格 | ST7735S 数据手册上限约 15 MHz，实测可用但不保证每一片都稳；偶发花屏先降 SPI 分频 |
| PA6 一脚两用 | flash MISO 与屏 D/C 共用，NOR 操作与屏刷新必须串行，排针 SPI 只有写通路只能读回 |
| 无复位/BOOT 键 | 救砖要靠短接 `USB_D+`/`3.3V` 焊盘 |
| standby_mode 4 未实现 | 预留值，行为等同四角白方块静止 |
| 只支持 CDC | 不再声明原厂的 HID 接口，原厂上位机的 HID 通道用不了 |
| OTA 镜像 ≤48000 B | 固件里的硬上限（应用区到 `0xF000` 为止、共 60 KB）；超了 `0A 12 01` 直接拒绝 |
| 固件体积受 `0xF000` 限制 | `.data` 载入末尾超过 `0xF000` 时 `link.ld` 直接链接失败，不会产出“能烧但会踩掉体检页”的镜像 |
